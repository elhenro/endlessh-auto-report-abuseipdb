# Security

Report vulnerabilities privately via GitHub: **Security** tab, **Report a vulnerability**.
Please do not open public issues for security problems.

Design notes relevant to security:

- The tarpit never reads from a client, so nothing a client sends is ever parsed. It uses the peer address, a typed `IpAddr` and not text, and peeks at the first 4 bytes to compare them with `SSH-`; those stay unread in the kernel. The only network input parsed is the HTTPS response from AbuseIPDB or the webhook (status and headers; at most 200 bytes of an AbuseIPDB error body, logged with control characters blanked). `tests/security.rs` enforces the never-reads property.
- The AbuseIPDB token is held in memory and sent in one request header. It never appears in argv or in a child process environment (there are no child processes). API calls refuse redirects and plain http.
- The docker image is a static binary on distroless (no libc, shell or package manager), runs as `nobody` with a read-only root filesystem and no capabilities, marks itself non-dumpable so a host process under the same uid cannot read it through `/proc`, and on a fresh install gets the token as a file so `docker inspect` does not show it. The systemd unit runs as a dynamic user with no capabilities (a socket unit owns the port), a syscall filter and `MemoryDenyWriteExecute`.
- Direct dependencies are `ureq` (rustls), `url` and `socket2`, plus `libc` for a few constants, `prctl` and a signal handler; the lockfile holds 67 crates with everything they pull in. Dependabot tracks them, `Cargo.lock` is committed, CI runs `cargo audit` daily and before every image is published, and the binary records its crate list so image scanners can see them.
- Images are built without a shared cache and carry a signed build attestation: `gh attestation verify oci://ghcr.io/elhenro/endlessh-auto-report-abuseipdb:latest --owner elhenro`. The release binaries carry one too, and the installer checks it with `gh attestation verify` when `gh` is installed: the checksum alone only proves the download survived the network.
- Everything an unauthenticated client can drive is bounded: one dedupe key per network with a hard cap (250k per sink, thinned early past it rather than growing), one log line per connection for reports but at most a counted line a minute for skips (a flood cannot bury the reports or fill the log), event files capped per day and deleted from the old end past the retention budget, and the audit file rotates into `reportedIps.txt.old` once it passes `REPORTED_MAX_MB` instead of growing forever, and `TARPIT_MAX_CLIENTS` plus the per-network share on sockets.
- The tarpit marks itself non-dumpable; if the kernel refuses that call it says so in the log rather than running on silently, since the token would then be readable through `/proc` by a process with the same uid.
